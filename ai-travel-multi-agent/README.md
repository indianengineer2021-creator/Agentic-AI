# AI Travel Planning Multi-Agent System

This repository is the initial scaffold for a production-style travel planner built with Python, LangChain, LangGraph, Gemini, Grok, Streamlit, ChromaDB, and LangSmith.

## Current phase

This is Phase 1 of the development plan:

- Create the project structure
- Add the dependency list
- Set up environment variables and git-ignore rules
- Prepare the foundation for the multi-agent implementation

## Planned architecture

The final system will include:

- Streamlit UI for trip input
- LangGraph supervisor orchestrating specialized agents
- Gemini-powered planning and retrieval
- Grok reviewer for critique and validation
- ChromaDB vector store for travel knowledge retrieval
- LangSmith tracing and observability
- Pydantic models for strong validation

## Structure

The project is organized into the following major directories:

- `agents/` for specialized travel agents
- `graph/` for LangGraph workflow state and orchestration
- `llm/` for LLM configuration
- `rag/` for travel knowledge and embeddings
- `models/` for Pydantic schemas
- `tools/` for mock APIs and future integrations
- `data/travel_knowledge/` for document-based travel knowledge
- `tests/` for validation and workflow checks
- `utils/` for shared helpers

## Running

This scaffold is a starting point only. The full application implementation will be added in later phases.

## Rebuilding the travel knowledge vector store

The RAG component uses Gemini's `gemini-embedding-001` model for text embeddings. Set `GEMINI_API_KEY` in `.env`, then rebuild the local ChromaDB collection after changing embedding models:

```powershell
.\venv\Scripts\python.exe -m rag.build_vectorstore
```

The build command recreates the `travel_knowledge` collection so vectors generated by an older embedding model are not mixed with the new model. Rebuild it before starting the app if you previously created the vector store using a different embedding model.
